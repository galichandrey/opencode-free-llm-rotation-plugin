# opencode-model-rotation

Плагин **OpenCode V2**: автопереключение между бесплатными моделями `opencode/*-free` по кругу (round robin), когда текущая упирается в лимит (HTTP 429 / «quota exhausted»).

## Как работает

1. Пул моделей берётся из markdown-файла (по умолчанию `~/src/opencode_free_models.md`) — все модели вида `provider/model`, найденные в бэктиках. Файл недоступен → используется встроенный список-фолбэк.
2. Исключение: `nemotron-3.5-lightning-free` (слабая) не попадает в пул никогда — задаётся в `options.exclude`, можно расширить.
3. Хук `session.hook("retry")`: если модель из пула падает — ошибки делятся на два ротируемых класса:
   - **rate** — 429 / «rate limit» / «quota» / «capacity»;
   - **unusable** — модель не обслуживаема прямо сейчас в обход лимита: `403` гео-блок («not available in your country»), таймауты, HTTP 5xx/unavailable.
   В обоих случаях модель помечается «остывающей» (10 мин), сессия переключается (`session.switchModel`) на следующую модель по кругу, повтор разрешён с задержкой 300 мс, и в сессию отправляется уведомление с причиной:

   > 🔄 [model-rotation] opencode/beam-free → opencode/big-pickle — недоступна (provider.auth 403): This model is not available in your country (попытка 2)

   Прочее (например, переполнение контекста) — не ротируется, логируется в файл плагина.
4. Страховка: хук `session.hook("prompt")` перед стартом хода переключает сессию с «остывающей» модели на свежую (любого класса — rate и unusable метятся одинаково) с тем же уведомлением («модель остывает после недавнего отказа»).
5. Если весь пул остывает — ход завершается ошибкой (без бесконечных повторов), следующий промпт снова ротируется по кругу.

## Установка (любой OpenCode V2)

В `opencode.json(c)` (глобально: `~/.config/opencode/opencode.json`, или локально в проекте) добавить в массив `plugins` / `plugin`:

```jsonc
{
  "plugins": [
    {
      "package": "/abs/path/to/opencode-model-rotation",
      "options": {
        "file": "~/src/opencode_free_models.md",   // источник списка моделей
        "exclude": ["nemotron-3.5-lightning-free"], // добавить свои — это заменит дефолт
        "retryDelay": 300                          // мс перед повторной попыткой
      }
    }
  ]
}
```

Или положить каталог пакета в `.opencode/plugins/` проекта (загружается автоматически), или в `~/.config/opencode/plugins/` (глобально).

Зависимостей нет — плагин самодостаточный (без `@opencode/plugin` в рантайме), работает и через локальный путь, и как npm-пакет (`npm publish` после + `opencode plugin add opencode-model-rotation`).

## Включение/выключение

Слэш-команда в чате:

| Команда | Действие |
|---|---|
| `/rotation` или `/rotation toggle` | переключить вкл/выкл |
| `/rotation on` / `/rotation off` | явно включить/выключить |
| `/rotation status` | статус: состояние, пул, остывающие модели |
| `/rotation list` | показать пул |
| `/rotation refresh` | перечитать md-файл (после его правки) |

Состояние сохраняется в хранилище плагина (переживает рестарт). Полностью отключить плагин — убрать запись из `opencode.json` (или префикс `-` в списке `plugins`), затем `opencode service restart`.

## Установка на этой машине (важно!)

Среда перекрывает глобальный конфиг OpenCode: переменная `OPENCODE_CONFIG_DIR=/home/orca/.config/orca/opencode-hooks/shared`, поэтому «глобальные» плагины сессий Orca автодискаверятся из `~/.config/orca/opencode-hooks/shared/plugins/`. Плагин установлен туда (копия каталога с синхронизацией при апдейте).

Дополнительно запись добавлена в классический `~/.config/opencode/opencode.json` (массив `plugin`) — для сессий без этого перекрытия. Один и тот же каталог плагина держится в `/home/orca/src/opencode-model-rotation` — при правке исходника скопировать `index.ts` в обе точки (или переустановить через npm-путь).

Если у TUI под root есть общий сервис `opencode serve --service` — для его сессий плагин нужно положить в конфиг-дир того пользователя (права root, самостоятельно не делалось).

## Диагностика

- Лог плагина: `~/.local/share/opencode/log/model-rotation.log` (загрузка, ротации, игноры не-429 ошибок, выгрузка).
- Консоль плагина сервером проглатывается — только файл.

## Известные наблюдения (2026-10-18)

- Прозрачный фейловер проверен вживую дважды: `glm-5.3-flash-free` → 429 → `big-pickle` → ответ; и `beam-free` → 403 «not available in your country» (класс unusable) → `big-pickle` → ответ. Оба — внутри одного хода.
- До ротации на unusable, `beam-free` был гео-заблокирован; теперь такие ходы выживают. Если модель должна быть исключена насовсем — `options.exclude`.

## Ограничения

- Исходный md-файл — статус-снапшот: плагин берёт из него только **список** моделей, статусы из него не читаются (они живут своей жизнью); контроль лимитов делает сама ротация.
- Если повторные попытки не перечитывают модель сессии, прозрачного фейловера внутри одного хода не будет — сработает страховка на следующем промпте (проверено ли это — см. тест).
- Захардкоженный фолбэк-список устареет со временем; файл в `options.file` — источник истины.
